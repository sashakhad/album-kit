# Suno run · version 9

Use Suno's official MCP connector first. A signed-in suno.com browser is the fallback only when the connector lacks a required capability. The user handles sign-in or captcha. Do not suggest an unverified free browser download. A take is a full mix; only a split produces stems.

## Preflight

Read the track sheet and the current owner Settings from `/api/owner/settings`. Follow the `reviewTakes` value saved on the round snapshot. It defaults to `public` when the owner has not chosen, including an older snapshot that omits the field. Refresh Suno's available model list, quality default, credits per generation, outputs per generation, remaining generation credits, download credits per take, and remaining download credits. Public review does not spend downloads; private review spends them per take. Use the saved `sunoModel` policy unless the owner requests a one-round choice; then send `sunoModelOverride` in `POST /api/owner/rounds`. If a saved model is unavailable, preflight blocks the round even when it names an alternative. Let the owner update Settings or explicitly request a one-round override after the capability and cost check. Do not use the sheet's old model if unavailable. Keep one resolved model for the round unless the owner specifically asks for a model comparison.

Call the owner round endpoint `/api/owner/rounds` with the current capability facts, verified hosting charge and eligibility, exact track count, and each prompt's track number, lane, ID, Style and writer attribution. Supply the generation cost's model ID separately from the rate. The route rejects missing prompt slots and title jokes in Style. Its snapshot and estimate include prompts, generations, expected outputs, generation credits, `downloadsPerTake`, and total `downloads`. When `reviewTakes` is `public`, both download figures are zero. When `reviewTakes` is `private`, `downloadsPerTake` is the account's download-credit charge for one take and `downloads` is that charge times the expected take count. Show the owner those download credits per take in the round estimate before they approve a private round. Explain any model migration. Include separately billed Cursor prompt work and hosting eligibility. If generation credits are insufficient, stop before the first paid call. If review takes are private and download credits are short of the per-take charge, stop before the first paid call. For a one-track Small test at two prompts and one standard two-output generation each, the illustrative estimate is 20 generation credits. Public review adds no download credits. Private review adds the account's download credits per take (4 download credits when the rate is one per take). Verify actual account charging first.

Show the complete estimate once and obtain an explicit allowance for this round. Tell the owner the estimate is ready before that question. Then authorize the saved round through `/api/owner/rounds/<id>/authorize` with `{ "approved": true }`. Tell the owner the round is authorized. Saving a limit in Settings or importing a preset is not authorization. Continue through generation, status checks, public stream storage or private take downloads, and voting within the allowance, without a second approval for those included steps.

## More like this requests

The owner can save a **More like this** request from Compare takes. `GET /api/owner/variations` lists durable requests with the selected track, parent filename, target number of new takes, optional edit instructions, status and linked round. Process only `requested` items; a `canceled` item is a tombstone that blocks a delayed retry. A saved request is a handoff, not Suno authorization. Do not start generation because a request exists. Keep any existing generation HOLD in force.

A request saved during a blind pass carries an opaque parent token in the owner response. The variation round route rejects planning while the pass remains blind. Wait for the pass to be revealed, then reread the request to obtain the canonical parent. Do not bypass the blind state by resolving the token through files, database access or another owner endpoint.

For a requested item, follow `song-prompts`: read the album brief and current owner constraints as context, then use the selected track sheet and parent take's saved provenance for the revision. Write a revised Style prompt that applies the owner's instructions while preserving the title-joke rule. Record the prompt writer's actual host, provider and observed model; leave unverifiable fields null. Use `POST /api/owner/rounds` with `variationRequestId`, `tracks: 1`, and exactly one prompt for the selected `trackNumber`. This route fixes the plan to one track and calculates the number of Suno calls from `requestedTakes` and the freshly checked outputs per generation. Its estimate may include more outputs than the target because Suno returns batches. Show the actual calls, expected outputs, credits, downloads, external prompt cost and hosting charge before seeking explicit approval. Repeat preflight if capabilities or the approval context changed. Never reinterpret the request count as an allowance to spend.

After approval, use the normal operation-ID ledger and collection procedure below. Assign each new take an unused canonical letter for that same track and set. Never reuse an old letter. Save its prompt and file in the selected track sheet, then call `/api/owner/provenance` for each output. The round snapshot supplies the parent filename, request ID and edit instructions to each take's saved provenance. `POST /api/owner/rounds/<id>/ready` marks the request ready only after the normal audio and provenance audit passes. The new files then appear under the selected track in Compare takes. If execution is unavailable, report the request as pending; do not show a completed generation state.

## Execute and resume

Submit every generation in the authorized round at once. Do not wait for one track to finish before starting another, and do not add prompts or generations beyond the allowance.

For each prompt and planned generation, create a stable operation ID and POST it to `/api/owner/rounds/<id>/jobs` **before** calling Suno. If the operation already exists, inspect it and resume; do not create another paid generation. Record every job first, then start those Suno calls together. Send only the sheet's Style paragraph, Title, resolved model and supported settings. If a required setting is missing, use the browser fallback for that prompt or stop precisely.

When Suno accepts a call, immediately PATCH that job with `status: accepted` and its provider job ID. Wait on the accepted jobs together. If acceptance is ambiguous and no ID was saved, inspect Suno's history before any retry. Do not send another paid request for a job that already has an operation ID.

When `reviewTakes` is `public`, publish the clip once it has finished streaming, with audio-settings `visibility: public`. A clip that is still streaming can answer `publish_pending: true`; wait until it is public before storing the stream. The playable review URL is `https://cdnN.suno.ai/<clip-id>.mp4`, the clip record's `video_url` from `https://studio-api.prod.suno.com/api/clip/<clip-id>`. Ignore `audio_url`; it is a placeholder and not playable media. Do not use CloudFront `media_urls` `.m4a` files. PATCH collection progress and outputs as `{ "takes": [{ "filename": "...", "outputId": "<clip id>", "clipId": "<clip id>", "streamUrl": "https://cdnN.suno.ai/<clip-id>.mp4", "downloaded": false, "uploaded": false }] }`; use `null` for an unavailable id. Never call audio-download for a take under review. An older `https://cdnN.suno.ai/<clip-id>.mp3` stream remains valid.

When `reviewTakes` is `private`, do not publish the clip and do not store a Suno stream URL. Call audio-download once per take, upload that file, and PATCH the take as `{ "filename": "...", "outputId": "<clip id>", "clipId": "<clip id>", "streamUrl": null, "downloaded": true, "uploaded": true }`. Each of those downloads spends the estimate's download credits per take. A song that stays private on Suno stops playing on the site, which is why this path stores a real file instead of a stream.

Count actual takes, not just expected takes. Record each take's prompt ID, actual Suno model, generation ID, settings, clip id, stream URL when the take is public, and round through `/api/owner/provenance`. Represent unavailable metadata explicitly rather than guessing. Mark a job `complete` only when every public review take has a stored stream URL, or every private review take has an uploaded file. A take that already has an uploaded file can still complete without a stream.

When review takes are public, do not download them. The site plays the stored public MP4 in its own player on Vote, Listen, Studio and `/final`, with the picture hidden, including scrubbing. Older Blob files and stored MP3 streams still play when that is what the take has. If a stored link is missing or is not that clip's public MP4, save the clips as `[{ "id" }]` (a playable `audio_url` is optional) and run `pnpm takes:refresh <clips.json>`. Refresh reads the studio clip record and stores `video_url` when `is_public` is true. If the clip is not public, it reports `publish the clip on Suno`. If capabilities differ from the estimate, pause only the affected step and show the precise difference; never silently expand the batch. When review takes are private, skip that refresh. The uploaded file is what plays. Do not publish the clip to obtain a stream after the owner chose private.

On the public path, only a final pick gets a real file. Export the WAV from Suno Studio when the account is Premier; Studio exports do not count toward the 60-song monthly download cap. Otherwise call audio-download once for that song, which counts as one download. Never use audio-download for a take that is still under review. When `reviewTakes` is `private`, each review take is already a downloaded file, so do not download it again. Final picks are stored as real files either way.

Before you say takes are playable, run `pnpm takes:verify`. Send the owner its line. That line reports how many stored streams returned 200. Say they are playable only when every stream returned 200. If any are waiting to be published on Suno, report that count and do not call those takes playable. Do not paste stream URLs or the album key.

Before sending a voting link, POST `/api/owner/rounds/<id>/ready`. It verifies every planned job is complete and every recorded take has matching provenance and stored audio; report any named blocker it returns. Check actual output counts against the estimate, audio playback and the site's visibility. Run `pnpm owner:link /vote` in the album checkout and give the owner **Compare takes as owner** in their private chat. They tap **Continue as owner**. An owner link works once and stays valid for 7 days. After Continue as owner, that browser stays signed in. Create a fresh one for another browser, or if this one expires unused. Never paste the permanent album key into chat or a URL.

Read `listenerVoting` and `visibility` from `pnpm album:settings` before sharing.

- Public: share `/listen`. It plays final picks and, when listener voting is on, previews with links to Compare takes.
- Private: create a listener invitation with POST `/api/owner/invites` or Settings → Sharing. Its secret is in the URL fragment. It grants listener access only.
- Unset: keep the album unshared until the owner chooses visibility. Owner links still work.

As soon as a track's takes are stored, publish or upload them, refresh their streams, and run `pnpm album:progress`. That command checks the live site. If it prints a `Track` line, that track is already on the site. Send the owner that line immediately, including `Site:`. Do not wait for other tracks. When listener voting is on, the link is Listen. Otherwise it is Compare takes. If the owner may be signed out, run `pnpm owner:link` with that path and paste the `Owner:` line too. The secret stays in the URL fragment. Never put the album key in the message or a query string.

Do not say takes are still generating, or that nothing is ready, until `pnpm album:progress` or the Suno job status says so. A `Track` line means that track is ready even when other tracks are not. If the command says progress was unread, open the site and do not invent a status. The count looks like `Round 1: 36/90 done, 72 of 180 takes ready.` Do not go silent until the whole album is done. Every setup and round message includes the site URL. When the round is ready, open Vote and confirm it lists takes. If the page says takes are being generated, or takes are waiting to be published on Suno, report that sentence and do not call the round ready. Then run `pnpm owner:link /vote` and paste its `Site:` and `Owner:` lines. When visibility is private or still unset, the owner link is required in that message.

If listening mode is blind, do not show identifying prompts or model details in chat, filenames, downloads or public routes. If the owner has already seen assignments, say the current round is exposed. Follow `publish` for sheet and log changes when permitted.
